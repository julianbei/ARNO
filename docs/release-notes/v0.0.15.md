# ARNO 0.0.15

**Theme: several worktrees, one server.** A tool call can now name the git
worktree it acts in. Nothing changes for a session that works in one
directory: a call that names no worktree behaves exactly as it did in 0.0.14.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/julianbei/arno/main/install.sh | sh
```

`go install github.com/julianbei/arno/cmd/arno-mcp@latest` and the image
`ghcr.io/julianbei/arno-mcp:v0.0.15` carry the same build.

## The `root` argument

```
arno.grep         query=parseHeader                         # the session's workspace
arno.grep         query=parseHeader   root=/repos/wt-spell  # a sibling worktree
arno.replace_text path=src/a.ts ...   root=/repos/wt-spell  # written there, not here
```

Every tool takes it except `workspace`, `telemetry`, `events`, `job_status`
and `job_output`, where a worktree means nothing. `arno.workspace` with no
path lists the worktrees of this repository and marks the one served by
default.

## Why this exists

An MCP stdio server is one process per client connection, and a request
carries no caller identity. A session and the subagents inside it therefore
share one server and one stream, and the server cannot tell them apart.

0.0.13 answered issue #3 with `workspace path=`, which repoints the whole
server. That is right for one caller. For two it is worse than the original
bug: switching for one silently sends the other's reads, edits and
diagnostics to the wrong tree, with no error anywhere. Issue #4 reported
exactly that, from a fleet running six sessions plus subagents across sixty
per-PR worktrees.

Naming the worktree in the call is the only thing that works over a shared
stream, because the caller is the only party that knows which tree it means.

## What a worktree costs

Each is a full workspace — its own symbol index, language servers, revision
counter, checkpoints and `.arno/`. Revisions and checkpoints do not carry
between worktrees; they describe different trees.

At most three stay open at once, least recently used evicted first, and the
session's default is never evicted. `ARNO_MAX_WORKSPACES` changes the bound.
The bound is the point: jdtls or rust-analyzer on a large repository is
hundreds of megabytes, and sixty worktrees must not mean sixty sets of them.
Eviction closes language servers and touches nothing on disk; the next call
into that worktree reopens it.

## A path in the wrong worktree now says so

```
outside the workspace: /repos/wt-spell/plan/README.md is not inside the
workspace root /repos/main

/repos/wt-spell/plan/README.md is in /repos/wt-spell, another worktree of
this repository. Act there with root=/repos/wt-spell and path=plan/README.md,
which leaves this session's workspace where it is.
```

## Containment is unchanged

A `root` is checked against `git worktree list` for the repository the server
was started in. Anything else is refused and the refusal lists the valid
targets. The argument widens which trees of *this repository* a server can
reach; it does not widen which repositories it can reach, and it is not a way
to write to an arbitrary directory.

## Changed

- `workspace path=` no longer closes the workspace it leaves. It stays open,
  so switching back is free until it is evicted.
- The core `tools/list` is about 1.3 KB larger, because `root` is declared on
  every tool it applies to. An argument an agent cannot see is an argument it
  does not use, so it is not hidden behind a flag.

## Known limitations

- Windows is not supported.
- One server serves one repository. Two repositories are two servers.
- Two rooted calls are still serialised: the MCP loop handles one request at
  a time. What changes is that they no longer corrupt each other's view.
- Exact references, cross-file rename and type errors on edit need that
  language's server installed; without one ARNO still answers and labels the
  answer approximate.
- Kotlin has no support yet.
- Telemetry is local only and never transmitted.
