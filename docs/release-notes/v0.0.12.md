# Arno 0.0.12

**Theme: a name of its own.** Jade is now Arno — Agent Repository Navigation
& Operations. Nothing you have installed stops working today: the old tool
names, variables and workspace directory keep answering for one more release,
each saying what to change.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/julianbei/arno/main/install.sh | sh
```

This installs `arno-mcp`. The old `jade-mcp` binary stays where it is until
you delete it, and the old repository URLs redirect, so a bookmarked link or
an existing clone keeps working.

Then point your MCP client at the new command:

```json
{"mcpServers":{"arno":{"type":"stdio","command":"arno-mcp","args":["--root","/absolute/path/to/repo","--tools","core"]}}}
```

`go install github.com/julianbei/arno/cmd/arno-mcp@latest` and the image
`ghcr.io/julianbei/arno-mcp:v0.0.12` work as before under the new names.
macOS and Linux; Windows isn't supported
([issue #2](https://github.com/julianbei/arno/issues/2)).

## Why rename

Jade is ambiguous in software: other products carry the name, there is a prior
trademark conflict, and other MCP projects already use it. That costs
searchability and adds legal risk as the project grows. Renaming at 0.0.x is
far cheaper than renaming once the name has spread through packages,
integrations and user configs.

## What changed

| Was | Is |
| --- | --- |
| `jade-mcp` | `arno-mcp` |
| `jade.find`, `jade_find` | `arno.find`, `arno_find` |
| `JADE_*` | `ARNO_*` |
| `.jade/` | `.arno/` |
| `github.com/julianbei/jade` | `github.com/julianbei/arno` |
| `ghcr.io/julianbei/jade-mcp` | `ghcr.io/julianbei/arno-mcp` |
| `io.github.julianbei/jade` | `io.github.julianbei/arno` |

## What still works, and for how long

Until the release after this one, Arno accepts every old spelling and prints
one deprecation line on stderr saying what to use instead:

- **Tool names.** `jade.find` and `jade_find` resolve to `arno.find`.
  `tools/list` advertises only `arno.*`, so no agent learns the old names.
- **Variables.** `JADE_*` is read when the matching `ARNO_*` is unset, in both
  the server and the install script.
- **Workspace state.** An existing `.jade/` directory is still read, so
  declared commands and project config survive the update untouched.

To finish the move: re-run the install script, rename the server entry in your
client config, `git mv .jade .arno`, and delete the old `jade-mcp` binary.

The Go module path and the container image have no aliases. Versions published
under the old names keep working; new ones appear only under the new ones.

## Also in this release

**Every tool is annotated.** All 31 tools carry MCP's behaviour hints — 16
read-only, 5 that change files but destroy nothing, 10 that can overwrite or
remove — so a host can auto-approve reads and treat deletion with care. A test
fails for a tool without an entry.

**Tool definitions are graded in CI.** Every push runs
[TDQS](https://tdqs.dev), the scoring Glama's registry uses: `lint` on both
tool sets, and the full rubric on pushes to main, failing below tier B. The
descriptions of `delete_file`, `run_tests`, `create_file` and
`declare_command` now say when to use them and what they do to existing state;
`create_file` no longer points at tools the core profile does not include.

## Known limitations

- **Directory listings lag the rename.** The Glama listing and the
  awesome-mcp-servers entry follow over the next days; the old MCP Registry
  listing is marked deprecated and points at the new one.
- **The container image** has no git, gopls or build tools inside;
  `references` and `rename` fall back to text and `changes`/`diff` are off.
- **Windows isn't supported.** Upvote
  [issue #2](https://github.com/julianbei/arno/issues/2) if you'd like it to be.
