# ARNO 0.0.17

**Theme: many sessions, one project.** For fleets of sessions working in
different git worktrees of the same repository at once: a way to make a write
from a session that has not said which worktree it works in impossible rather
than merely reported, and a formatter fix for Rust workspaces. Nothing changes
for a session that works in one directory.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/julianbei/arno/main/install.sh | sh
```

`go install github.com/julianbei/arno/cmd/arno-mcp@latest` and the image
`ghcr.io/julianbei/arno-mcp:v0.0.17` carry the same build. Reconnect your MCP
client afterwards; the tool catalog is fixed at connection time.

## Strict mode

Set `ARNO_REQUIRE_WORKSPACE=1` in the server's environment, once. In a
repository with more than one worktree, any call that can change something —
edits, creates, deletes, `run_command`, `revert` — is then refused until the
session has said which worktree it works in. Reads are never refused.

```
arno.create_file not run: this repository has 3 worktrees and this session has
not said which one it works in, so the change would land in /repos/main, the
server's start worktree, which may not be yours. Nothing was written.

Say it once with workspace path=<your worktree> — after that no call needs
root — or pass root=<your worktree> on this call.
```

### Why

Every Claude session starts its own server, usually from the shared main
checkout. A session that later moves into its own worktree keeps a server
pinned to the checkout it started in, and so does every other session in the
same position. They all default to the same tree.

A session that forgot to say which worktree it was in wrote 1,387 lines into
the shared checkout, on top of other sessions' work, and nothing complained:
the paths were valid. 0.0.16 made the edit response end with the tree it acted
in. That reports the mistake after it has happened. Strict mode stops it.

### How a session uses it

```
arno.workspace path=/repos/wt-feature        # once, at the start
```

After that no call needs `root`. The session's subagents share its server, so
they inherit the same worktree. A subagent assigned to a different worktree
passes `root=<path>` on its own calls; put it in that subagent's brief.

- Naming the worktree the server started in counts. A session that really is
  working there has nothing to switch, but strict mode still wants it said.
- Listing the worktrees (`workspace` with no path) does not count.
- `root=` on a call satisfies that call only. It does not declare the
  session's own worktree.

### What it does not do

- It is off by default. A repository with a stray second worktree and a
  session working in the first is the ordinary case, and refusing it would
  punish everyone for a failure only a fleet has.
- A subagent working in a different worktree from its parent, without `root=`,
  still writes into the parent's declared worktree. The server cannot tell the
  two apart on one connection. The edit response ends with
  `acted in <path> (this session's declared worktree; …)` so it shows in the
  same turn.
- It does not see across sessions. Two sessions that declare the same worktree
  are still two sessions in one tree; the revision checks that stop them
  overwriting each other's edits apply as before.

## rustfmt formats only the file you edited

Run on a file, `rustfmt` also rewrites every file that file declares with
`mod x;`. Editing `lib.rs`, `main.rs` or a `mod.rs` reformatted the whole
module tree below it. A fleet session reported fourteen files it had not
touched reformatted after editing two; that is the likely cause, though that
session has not confirmed it.

ARNO now formats through standard input, which formats exactly the content it
is given. It still honors the nearest `rustfmt.toml`, and a config nearer the
file wins, as it does for `cargo fmt`.

## rustfmt uses the project's edition

`rustfmt` takes the edition from `cargo fmt`, not from `Cargo.toml`. Run on a
file it assumed 2015, where `async` is a syntax error: it refused, and the file
was silently never formatted. ARNO now reads the edition from `Cargo.toml`, or
from the workspace for `edition.workspace = true`. If the project's own
`rustfmt.toml` sets an edition ARNO passes none, because a flag would override
the config the project declared. With no manifest at all it uses 2021.

## ruff.toml

A `[format]` section in `ruff.toml` or `.ruff.toml` now counts as the project
declaring ruff, as `[tool.ruff.format]` in `pyproject.toml` always did. Without
the section it is a linter config, and nothing runs.

## Respecting local formatting rules

ARNO formats only files it edited, with a formatter the project declares, using
that project's own config and — for Node and Python — its own binary. A
repository that declares nothing gets files back exactly as edited. Since
0.0.16 an edit also keeps the file's line endings and trailing-newline state.

ARNO does not interpret `.editorconfig`. If a project's only formatting rules
live there, ARNO will not apply them.

## Known limitations

- Windows is not supported.
- One server serves one repository, though any of its worktrees (0.0.15).
- Exact references, cross-file rename and type errors on edit need that
  language's server installed; without one ARNO still answers and labels the
  answer approximate.
- Kotlin has no support yet.
- Telemetry is local only and never transmitted.
