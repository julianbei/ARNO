# ARNO 0.0.13

**Theme: the tools say what they cost you.** This release came out of a
benchmark round that measured, for the first time, how much of every tool
result an agent actually uses. Three of the four changes below are things that
round found: a refusal that sent agents back to re-read the wrong files, edit
responses burying the one new error under hundreds of old ones, and agents
guessing command names in a repository that had declared none.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/julianbei/arno/main/install.sh | sh
```

`go install github.com/julianbei/arno/cmd/arno-mcp@latest` and the image
`ghcr.io/julianbei/arno-mcp:v0.0.13` carry the same build.

## Highlights

### An edit response lists what the edit changed

An edit used to return every diagnostic in the file. On a Django test module
under pyright that meant 583 lines of pre-existing errors in the response to a
one-line change — the agent had to find its own mistake in someone else's.

ARNO now snapshots a file's diagnostics before the write and lists only what
the edit added, with a count of the rest. Where no snapshot exists it returns
at most 12, nearest the edit first.

### A stale-revision refusal says what moved

`edit rejected: stale revision` was the entire message. It now names both
revisions and every file ARNO edited between them:

```
expected r3, workspace is at r5; changed since r3: a.go, b.go
— read those again before editing, then retry with expectedRevision r5
```

So the agent re-reads exactly what changed instead of re-reading everything or,
worse, carrying on with a stale picture. `errors.Is(err, ErrStaleRevision)`
still holds.

### Commands ARNO can see but nobody declared

`run_command`'s listing, its unknown-name refusal, and `capabilities` now also
show commands found in the repository's own manifests — npm scripts and
Makefile targets — that have not been through `declare_command`. Capped at 10,
recognisable operational names first, and anything `check` already covers for
build, typecheck or tests is left off so the suggestion never duplicates what
`capabilities` reports.

Detection is read-only. `declare_command` remains the only path that writes
`.arno/commands.json`; a candidate is a suggestion, never a write.

This closes a failure class the benchmark measured directly: agents inventing
`run_command` names like `test-unit` and `model_formsets_tests` against a
repository that had declared nothing.

### The Jade names keep working for one more release

If you are still on the old spellings, nothing breaks today.

0.0.12 warned that `jade.find`, `JADE_*` and `.jade/` would stop working after
that release. They keep working through 0.0.13 instead, and are deleted in the
release after this one. 0.0.12 and 0.0.13 shipped a day apart, and a grace
period counted in releases rather than days is not notice for anyone who
installed under the old name. The deprecation lines now name 0.0.13.

Migrating is still two moves: rename the tools in your client config from
`jade.*` to `arno.*`, and `git mv .jade .arno` in any repository that has one.

## Also in this release

- `--tools core+<tool>` lists the core profile plus named tools, for
  benchmarking a candidate against `core` without a second hardcoded list.
  The first candidate, a read-only batch tool, was never called in 15 runs
  and did not ship.
- The benchmark derives each task's gold set from the reference fix, and the
  insight report gains a yield section: gold file and line recall, gold lines
  per 1k tokens of tool result, and the call that first surfaced one.
- `bench/tasks/django.json` — three real fixes in a 7,000-file repository.

## Known limitations

- Windows is not supported.
- Exact references, cross-file rename and type errors on edit need that
  language's server installed; without one ARNO still answers and labels the
  answer approximate.
- Kotlin has no support yet.
- Telemetry is local only and never transmitted.
