# ARNO 0.0.14

**Theme: the rename is finished.** The names Jade used stopped working in this
release, on the schedule 0.0.12 and 0.0.13 printed on stderr every time one was
used. Nothing else changes: if you are already on `arno.*`, `ARNO_*` and
`.arno/`, this release behaves exactly like 0.0.13.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/julianbei/arno/main/install.sh | sh
```

`go install github.com/julianbei/arno/cmd/arno-mcp@latest` and the image
`ghcr.io/julianbei/arno-mcp:v0.0.14` carry the same build.

## What stopped working

### Tool names

`jade.find` and `jade_find` are gone. A call to one now fails the way any
unknown tool does, and the refusal names the replacement:

```
unknown tool: jade.grep (did you mean arno.grep?)
```

`tools/list` never advertised the old names, so an agent that reads the catalog
was never affected. What breaks is a client config, script or prompt written
before the rename. The fix is in the error message.

### Environment variables

`JADE_VERSION`, `JADE_TELEMETRY`, `JADE_WORKSPACE` and the rest are ignored —
silently, since there is no longer anything watching for them. Use the `ARNO_*`
spelling. `install.sh` no longer translates them either.

### The `.jade/` directory

A workspace with only a `.jade/` directory now reads as having no declared
commands, no project file and no telemetry history. Nothing is deleted; it is
simply not read.

```sh
git mv .jade .arno     # tracked
mv .jade .arno         # untracked
```

That keeps your declared commands, `project.json` and the telemetry log
together. Doing it per repository is the whole migration.

`internal/compat` is deleted with them, along with the deprecation warnings it
printed.

## Known limitations

- Windows is not supported.
- Exact references, cross-file rename and type errors on edit need that
  language's server installed; without one ARNO still answers and labels the
  answer approximate.
- Kotlin has no support yet.
- Telemetry is local only and never transmitted.
